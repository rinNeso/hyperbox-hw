# 2026-09-15 — the p10k configuration wizard hijacks every finished update

## Symptom

After `cachy-update` finishes, the window does not sit showing the update's
output. It shows Powerlevel10k's configuration wizard:

```
Does this look like a diamond (rotated square)?
(y)  Yes.  (n)  No.  (q)  Quit and do nothing.
```

## Not an update bug

The chain, top to bottom:

1. `~/.local/share/applications/arch-update.desktop` (our konsole→kitty
   override) ran `kitty --hold -T "Cachy-Update" -e arch-update`.
2. kitty's `--hold` is documented as *"Remain open, **at a shell prompt**, after
   child process exits."* It does not merely freeze the window — it spawns an
   interactive `$SHELL` once the child exits.
3. `$SHELL` in the Plasma session is `/usr/bin/zsh`, even though the passwd
   login shell is `/bin/fish` (`systemctl --user show-environment` reports fish;
   plasmashell's own environ reports zsh).
4. `~/.zshrc` is one line: `source /usr/share/cachyos-zsh-config/cachyos-config.zsh`.
5. That file sources powerlevel10k unconditionally at line 88, then at line 101
   does `[[ ! -f ~/.p10k.zsh ]] || source ~/.p10k.zsh`.
6. There is no `~/.p10k.zsh`. Powerlevel10k with no configuration runs its
   configuration wizard.

So every finished update opened a fresh interactive zsh, which had no p10k
config, which took over the window.

## Cause

`--hold` was added to the override on 2026-09-13 to "keep the window open after
the update exits so warnings stay readable". The intent was right; the flag was
wrong. `--hold` achieves persistence *by starting a login shell*, which drags in
the entire zsh startup path. What was wanted is a pause, not a shell.

## Fix

`bin/cachy-update-window` — a `/bin/sh` wrapper that runs `arch-update`, prints
the exit status, and blocks on `read`. No shell startup, no rc files, nothing
sourced. The desktop entry now execs the wrapper:

```
Exec=kitty -T "Cachy-Update" -e /usr/local/bin/cachy-update-window
```

`check.sh` fails if `--hold` reappears in that desktop file.

## Left alone, worth knowing

`~/.p10k.zsh` still does not exist, so *any* interactive zsh on this machine
will still open the wizard — this fix only stops the update window from
starting one. If zsh is ever used directly, either run `p10k configure` once or
stop `cachyos-config.zsh` from loading p10k. Also unexplained: why the Plasma
session exports `SHELL=/usr/bin/zsh` when passwd has said `/bin/fish` since
2026-08-10.
